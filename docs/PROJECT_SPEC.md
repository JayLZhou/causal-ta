## 产品定位

帮助学生找到卡点，并通过一个有针对性的教学动作独立跨过去。个人学习是主流程；教师课程工具和教学研究是支撑能力。产品应逐步支持个人工作区、跨会话可追溯记录、自己的材料和问题；这些能力的当前边界见 `PERSONAL_TA.md`。首页应让学生直接进入学习，科研模型与证据说明可展开查看。

“覆盖所有计算机与数学课程”通过统一接口和课程包扩展实现，按模块逐步验证覆盖。支持表达某类课程，不等于已经提供该类课程的高质量内容。

## 三种对象必须分开

1. 领域模型：代码运行、网络连通、函数变换或形式化推导的可检查机制。
2. 学生模型：对学生可能持有的误概念的可修正假设。答错也可能来自读题、粗心或疲劳，不应直接确诊知识缺失。
3. 教学策略模型：某种追问、反例或提示对后续独立表现的影响。它需要干预数据验证，不能由前两类图自动推出。

当前代码实现第 1 类的有限模型、第 2 类的规则式误概念证据和后续检查，以及隔离评分的可选联网 TA。第 3 类已有可选策略随机分配和完整分母报告，但仅以合成数据验证；没有统计校准、真实教学效应或学习策略优化结论。

## 目标教学交互

学生提交题目、代码或推导步骤 → TA 给出一个低负担诊断问题 → 根据回答更新候选误概念 → 选择最小提示、反例、可执行实验或先修复习 → 学生自行修改 → 对新题进行无帮助迁移检查 → 更新证据和下一步。

示例：线性代数中，学生误以为“行列式为 0 就没有解”。TA 不立刻贴完整解答，而给出两组奇异矩阵系统，让学生对比相容性。迁移题检查其是否能区分无解和无穷多解。这里数学判断由秩条件验证，学生误概念保留为假设，提示效果由后续学习数据检验。

## 分层架构

| 层 | 责任 | 关键约束 |
|---|---|---|
| 学习界面 | 编辑代码/公式、预测、提交、追问、回顾 | 学生能看到正在验证什么 |
| Tutorial Runtime | 管理诊断、干预、练习、迁移阶段 | 不把有提示成绩当独立成绩 |
| Course Pack | 目标、先修、误概念、题目、rubric、材料引用 | 可版本化；教师可修订 |
| Domain Adapter | 测试代码、求反例、计算或检查证明 | 可信检查器与 LLM 文字分开 |
| Student State | 存储证据、误概念假设、掌握不确定性 | 不把一次答错归为稳定能力 |
| Teaching Policy | 选择提问/提示/复习并记录选择概率 | 信息增益与学习效益分开建模 |
| LLM Adapter | 生成自然语言追问和解释 | 不改写评分标准；输出受结构约束 |
| Evidence Store | 版本、事件、策略、迁移结果 | 支持复现和数据撤回设计 |

## 课程适配路线

| 课程类型 | 领域检查器 | 合适的教学动作 |
|---|---|---|
| 编程 / 数据结构 | 固定测试、受控执行、复杂度反例 | 最小失败输入、预测输出、局部提示 |
| 算法 | 小规模穷举、性质测试、证明 rubric | 反例、边界条件、循环不变式追问 |
| 系统 / 网络 / 数据库 | 隔离故障实验、查询结果、执行计划 | 区分原因的测试、单变量干预 |
| 微积分 / 线性代数 | 数值与符号检查、定义域约束 | 极端例子、参数变换、条件检查 |
| 概率统计 | 可复现采样、枚举和解析校验 | 条件化对比、生成机制实验 |
| 离散数学 / 证明 | 有限模型反例、人工或形式化 rubric | 找缺失条件、验证量词、补关键步骤 |

检查器覆盖不了的开放证明必须显示“需教师复核”，不能把 LLM 自评当可靠验证。

## 1000 stars 的执行思路

先让可分享的演示回答一个明确问题：“学生为什么会错，TA 怎样用一问或一例帮助他自己发现？”提供无需注册、无需 key 的演示，有教师模板和可复现实验。首批贡献任务以新课程包、误概念测试、解释质量审查为主，而不是让新人先理解整个系统。

发布材料可以准备；面向教师或社区发送消息需用户明确指定并授权。当前不承诺星标数量、期限或论文录用。若使用量低，优先修复接入成本和教学价值，而非扩张宣传范围。
